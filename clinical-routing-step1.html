Step 1 of the routing mission · Freebuff

What I built: a 16-query clinical routing axis

Your repo studies what happens when a multi-agent system sends a task to the wrong agent. Step 1 adds a second, clinical task set alongside the existing generic one — without touching it: four sub-agent destinations declared in code, sixteen text queries (four per destination) built from sample clinical scenarios, and a validator that proves the wiring. No routing pipeline yet — that is deliberately a later step.

  • tasks/clinical_tasks.json · 16 queries, 4 × 4
  • evaluate/clinical_agents.py · destinations + --validate
  • 4 agent prompts · handoff targets
  • Baseline tasks.json untouched

The four destinations

Declared once in CLINICAL_DESTINATIONS — each binds a name, a description, and the handoff target (the agent prompt file that would receive the task).

symptom_triage

Patient symptom descriptions → urgency classification (emergency / urgent / routine) + recommended action.

→ agents/symptom_triage_agent.txt

“Sudden crushing chest pain radiating to the left arm…”

drug_interaction_checker

Medication lists and drug pairs → adverse interactions, contraindications, monitoring.

→ agents/drug_interaction_checker_agent.txt

“Taking Warfarin, prescribed Amoxicillin. Check for interactions.”

medical_literature_search

Clinical evidence questions → what studies and guidelines say. Never personal advice.

→ agents/medical_literature_search_agent.txt

“Aspirin for primary prevention in adults over 60?”

general_code_math

Calculations and small functions on clinical data: scoring formulas, unit conversions.

→ agents/general_code_math_agent.txt

“Compute creatinine clearance (Cockcroft-Gault).”

How the pieces connect

Solid arrows are wired and verified today; dashed arrows are declared but not yet built.

The four destination chips each own exactly 4 of the 16 queries. The evaluator already loads the clinical file cleanly; scoring and routing hooks fail loudly by design until their step arrives.

Known limitations (stated plainly)

Scoring not wired yetStep 1 scope ends at destinations + data. Running the clinical set today fails fast with Unsupported task type rather than silently scoring wrong — the fix belongs to the scoring-dispatch step.
Pre-existing defect found, not fixed (out of scope)The baseline prompt files are rotated: math_agent.txt holds the extraction prompt, extraction_agent.txt the evidence-QA prompt, evidence_qa_agent.txt the math prompt. Any baseline run scores against the wrong system prompts.
Environment noteThis machine resolves python3, not python; README commands using plain python will fail as written.
